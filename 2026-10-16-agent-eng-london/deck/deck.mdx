<Slide tab="theory">

# One sentence, three parts

<Row align="flex-start" gap="1.6rem">
<Col>

### Optimization

There are metrics and you want them better: speed, compatibility, memory, signups.

The agent is the optimizer. Stochastic, tireless, not picky about how.

</Col>
<Col>

### Constrained

Some things must stay true whatever the metric says: the spec, security, no `unsafe`.

Gates, not weights. The optimizer never gets to trade them.

</Col>
<Col>

### Non-convex

There is no single downhill path. Plenty of places "work" but aren't good, and the optimizer will stop in one.

Someone has to poke it.

</Col>
</Row>

<p style={{ marginTop: '1rem' }}>My job moved from finding **x** to choosing **f** and **g**. Review is one of the **g**'s.</p>

</Slide>

# Constraints we couldn't afford before

<Row align="flex-start" gap="1.6rem">
<Col flex="1 1 55%">

The hosted Monty relay shipped last week with a `verification/` directory written alongside the code:

- **11 Dafny and 5 TLA+ models**: admission, lease replacement, dispatch, broker lifetime, recovery
- **13 Kani harnesses** that import the production decision functions, over the full input domain
- **86 implementation mutations** that must fail, so an always-deny implementation cannot pass
- An **eight-job CI matrix**, required whenever relay code changes; each proof receipt is bound to the hash of its inputs
- A README that says what it does **not** prove: the compiler, the scheduler, the deployed binary

</Col>
<Col flex="1 1 45%" className="small-code">

```dafny
predicate Safe(s: State, valid: set<int>,
               authLimit: nat, lookupLimit: nat,
               sessionLimit: nat) {
  s.lookups <= s.pending &&
  s.pending * s.authorized == {} &&
  s.sessions <= s.authorized &&
  s.authorized <= valid &&
  |s.pending| <= authLimit &&
  |s.lookups| <= lookupLimit &&
  |s.sessions| <= sessionLimit
}
```

<p className="caption">A year ago nobody would have paid for a Dafny proof of a WebSocket relay. When the agent writes it, the only question is whether the fence is worth having.</p>

</Col>

# What I'd do tomorrow

- **One objective.** Pick the metric. Turn every other thing you care about into a constraint with a threshold: "latency under 200 ms", not "also make it fast".
- **Gates, not weights.** If a violation is unacceptable it fails the build. Security is never a score.
- **Every incident becomes a permanent, executable constraint.** That is the job: given a bad solution, produce the cheap check it violates.
- **Make the loop fast and deterministic.** The verifier is your leverage; flaky or slow CI caps how hard you can push.

</Slide>

<Slide tab="lessons" fontSize="large">

# Where the metaphor breaks

- **Constraints are sampled, not proven.** CI checks points, not the region. Types and proofs are the exception, which is why the Dafny slide matters.
- **The optimizer can read the constraints.** A solver can't lobby you to relax a bound; an agent will edit the test. Fences need tamper-protection: branch protection, "never xfail", a human approval, credentials it doesn't have.
- **The real objective is a proxy.** Signups, revenue, "ease of use" aren't measurable until deployed. Goodhart's law applies to you, not just the model.

</Slide>
